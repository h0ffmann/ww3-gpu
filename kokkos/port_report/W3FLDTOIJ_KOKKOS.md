# W3FLDTOIJ_KOKKOS

**Status:** ported, phase 1 (translated). Not wired into WW3, not regtested: translation only,
no test run (the owner, 2026-10-16).

Output set-up: one output field name, as a user writes it in the namelist (`'HS'`, `'DIR'`,
`'WND'`), is mapped to its group `I` and field `J` in the output tables (`HS` is group 2, field
1), the indices of `FLG2D(I,J)` and `IDOUT(I,J)`. An unknown name gives `I = J = -1` and a warning
on the output processor. No floating-point arithmetic.

- (v) Fresh review 2026-10-16: `w3iogomd.F90` (`WW3-noaa/`) recompiled in the pinned `ww3` shell
  (gfortran 16.2.0) with the `flags.make` of WW3's CMake build under `switch_lab_shrd` plus
  `-fdump-tree-original` and `-fdump-tree-optimized-lineno`. The 97 (name, `I`, `J`, kind)
  regenerated by a script from the `jumptable` initializer of the original tree (98 entries, entry
  0 the default with null strings, every other entry low = high) and the stores of each `case`
  target: identical to `kCases`, `'U1'` and `'U2'` both `(10, 1)`, `'UNSET'` a bare `goto`; the
  preprocessed source has no `'D50'`, `'IC1'`, `'IC5'`, `'AHS'`, `'ACHA'`, `'OHS'`, `'THM'`,
  `'OCHA'` or `'DRY'`. `select_inc.c` and `string_intrinsics_inc.c` extracted from the nix store's
  `gcc-16.2.0.tar.xz` are identical to the translator's copies: `compare_string` is an
  antisymmetric total order (unsigned `memcmp`, then the tail against `' '`), so the binary chop
  and its final `selector <= high` check return an entry only on blank-padded equality, which
  `fstr_eq` computes; `string_len_trim` trims `' '` only. A throwaway differential in scratch
  (`/tmp/claude-1000/-home-hoffmann-code-ww3-gpu/900356d7-9a07-464f-88f0-492c00219d16/scratchpad/W3FLDTOIJ/rev/diff`):
  the preprocessed `W3FLDTOIJ` built with gfortran 16.2 `-O3` against the header built with the
  `openmp-release` flags and with ASan/UBSan, on 31,422 inputs (every key, with trailing blanks,
  NUL, a dropped or added character, lower case; bytes 0x00, 0x01, 0x09, 0x1F, 0x7F, 0x80, 0xFF;
  the uncompiled names; `LEN(FLD)` 6, 10 and 100; `US3DF(1)`, `USSPF(1)` in -1, 0, 1, 5;
  `IAPROC` equal and not equal to `NAPOUT`): `I`, `J` and the bytes written to `NDSEN` (12,362
  FORMAT 1004 and 45 FORMAT 1008 messages) identical (`cmp`, same SHA-256), no sanitizer report,
  no warning from the header. One defect found and fixed: the order-of-effects bullet put the
  `free` of the trimmed selector after the branch stores; it comes before them. No defect in the
  header.

## Arithmetic and semantics

Reference: the `-O3` object of `w3iogomd.F90` (`WW3-noaa/`) recompiled with the flags of WW3's
CMake Release build under `switch_lab_shrd` (gfortran 16.2.0, pinned `ww3` shell,
`-fdump-tree-optimized-lineno`); its disassembly is identical to the CMake object of `build_lab`
(v, `cmp` of `objdump -d`, 2026-10-16). Compared with a throwaway C++ unit (`w3fldtoij` called
directly and through `w3flgrdflag`) compiled warning-free with the `openmp-release` flags
(g++ 16.2.0), with ASan/UBSan at `-O0`, and with `nvcc_wrapper` (CUDA 12.9, `sm_89`,
`--fmad=false`, host code only; build only, never run), 2026-10-16.

- (v) No floating-point operation in either object.
- (v) Order of effects in the object: `I = -1`, `J = -1` (`:803-804`); `_gfortran_string_trim`
  of 6 bytes of `FLD`; `_gfortran_select_string` on a table of 98 entries; `free` of the trimmed
  copy (before the branch, not observable); the stores of the matched branch. The C++ does the
  same stores in the same order.
- (v) Table: the 97 (name, `I`, `J`) of the header's `kCases` equal the 97 of the object, entry
  by entry (a script read the jump table's strings and targets and each target's stores out of
  the GIMPLE and `diff`ed them with the header's table: identical). That includes `'U1'` and
  `'U2'` both giving `(10, 1)` (`:1164-1169`, a quirk of the Fortran, kept) and `'UNSET'`
  (`:1174`), whose target is the return: `I = J = -1`, no warning.
- (v) Selector: `TRIM(FLD(1:6))`. The object trims 6 bytes whatever `LEN(FLD)` is
  (`_gfortran_string_trim (&len, &pstr, 6, fld)`), so only the first 6 characters decide: a name
  of 7 or more characters matches the case its first 6 spell, if any (`'HSXYZW'` matches nothing,
  `'SDMHC'` needs exactly those 5 and a blank). The C++ trims trailing blanks of `fld[0..6)`.
  `string_len_trim` trims the blank `' '` only (`libgfortran/intrinsics/string_intrinsics_inc.c`,
  gcc 16.2.0, read 2026-10-16), and so does the C++.
- (v) Matching: `select_string` (`libgfortran/runtime/select_inc.c`, gcc 16.2.0, read
  2026-10-16) binary-searches the sorted table with `compare_string`, which is `memcmp` over the
  common length and then the rest of the longer string against blanks. Each entry is one value
  (low = high) and the 97 strings are distinct, so the search returns the entry whose string
  equals the selector under blank-padded equality, or the default; the C++'s linear scan with the
  same equality (`fldtoij_detail::fstr_eq`) returns the same entry.
- (v) `'USF'`: the object loads `US3DF(1)` (`data + (offset + stride) * span`) and tests `> 0`,
  the same as `.GE. 1`; the C++ tests `*us3df >= 1`. `'USP'` likewise with `USSPF(1)`. On failure
  `I`, `J` stay `-1` and, when `IAPROC = NAPOUT`, FORMAT 1008 is written with `'USF','US3D'` or
  `'USP','USSP'`.
- (v) Default (`:1175-1178`): `I = J = -1` again, then, when `IAPROC = NAPOUT`, FORMAT 1004 with
  `TRIM(FLD)` of the whole dummy (`_gfortran_string_len_trim (_fld, fld)`, not of `FLD(1:6)`).
- (v) Bytes of the warnings: a gfortran 16.2 program writing FORMATs 1004 and 1008 (copied from
  `:1181-1186`) to a file gave, read with `od -c`, four records for 1004 (an empty one, the
  `WARNING  : ` line with its trailing blank, the `REQUESTED OUTPUT FIELD <TRIM(FLD)> WAS NOT
  RECOGNIZED.` line, and an empty one for the closing `/`) and three for 1008 (no closing empty
  record). `fldtoij_message` builds the same bytes, each record ended by `'\n'`. The format
  strings are those of the object's `dt_parm.format` (lengths 115 and 168).
- ⚠ `@pre fld_len >= 6`. A dummy shorter than 6 characters makes the Fortran read past it
  (no bounds check in the Release build); the C++ reads 6 bytes too. Both callers pass 100 or
  10, so the case is not reachable at the pin.
- ⚠ The return code is a structural addition: the `fldtoij` hook of `iogo_w3flgrdflag.hpp`
  returns `void`, so the shim must carry a missing `write_formatted` to its own exit. Not built
  yet.
