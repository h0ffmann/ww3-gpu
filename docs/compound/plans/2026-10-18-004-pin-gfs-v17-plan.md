# Pin WW3 to NOAA's `production/GFS.v17` - Plan

## Goal Capsule

- **Objective:** `WW3-noaa/` and the fork's KOKKOS patch sit on the WW3 that NOAA's next
  operational GFS runs, so every parity result, timing and regtest of ww3-gpu is about the code
  GFS-Wave will use.
- **Authority:** AGENTS.md ("WW3 source is read-only", "Bit for bit", "Translate, don't
  improve"); the owner chose `production/GFS.v17` on 2026-10-18, in its own PR after #191.
- **Stop conditions:** a translated routine whose Fortran changed between the two bases and whose
  translation no longer matches it; a regtest difference that a Fortran/Fortran run does not
  reproduce. Either stops the pin move; it is never solved by keeping old Fortran.
- **Execution profile:** large; its own branch from `main` after PR #191 merges.

## Why GFS.v17 and not a release tag

Facts read 2026-10-18 (v, `git ls-remote --tags` and `gh release list -R NOAA-EMC/WW3`,
`git rev-list` in `WW3-noaa/`):

| Candidate | Commit, date | Against the pin `03adda91` (`develop`, 2026-10-05) |
|---|---|---|
| `develop` | `03adda91`, 2026-10-05 | the pin itself |
| release `6.07.1`, the only tag | 2019-04-19 | 404 commits older; before the CMake build the patch uses |
| `production/GFS.v16.3`, operational GFS-Wave today | `41e7c9ca`, 2025-02-21 | split 2020-03-04; 372 of the pin's commits missing, 18 of its own |
| `production/GFS.v17` | `7a23cd77`, 2026-05-14 | split 2025-11-26 (`9d0cb947`); 143 of its own, 31 of the pin's missing |

NOAA ships WW3 through `production/*` branches, not release tags. That `GFS.v17` is the next
operational GFS, and its implementation date, are not read in a NOAA notice ⚠ (the `noaa-notices`
skill is the place to check).

## What moves

`git diff --stat 03adda91 origin/production/GFS.v17 -- model/src`: 64 files, 11 661 insertions,
2 878 deletions (v). Every file of the KOKKOS patch changed upstream: `CMakeLists.txt`,
`cmake/switches.json`, `w3initmd.F90`, `w3srcemd.F90`, `w3wavemd.F90` (v). So did the Fortran of
two ported routines' modules, `w3pro3md.F90` (`W3XYP3`, `W3KTP3`) and `w3iobcmd.F90` (the
boundary output of U8) (v). `w3src4md.F90` (ST4) and `w3snl1md.F90` (the DIA), 66 % of the
resident wall time, did not change (v, absent from the name list). `wminiomd.F90` and
`w3iotrmd.F90` did not change either.

## Units

1. **Read GFS.v17's switch files and record them** (plan 3 of
   `2026-10-18-003-gpu-first-supervised-run-plan.md`): `model/bin/switch_NCEP_st4` and the switch
   the GFS.v17 workflow builds with ⚠ (where that file lives is not read). Run the `W3SRCE` gate
   of gap 1 on it: if `SEED` or `FLD2` is there, the Kokkos `W3SRCE` does not run for GFS-Wave.
2. **Diff the Fortran of every translated routine** between `03adda91` and `7a23cd77`, from
   `kokkos/ports.tsv`'s file:line columns. Each routine whose lines changed is listed with the
   hunk; its translation is updated in its own commit (translate, don't improve), with the static
   parity argument of ADR-0016 redone.
3. **Rebase the fork.** `WW3-noaa/` to `7a23cd77`; a new fork branch from it carrying the KOKKOS
   patch (`ww3-gpu/kokkos-pnt` after #191's pin bump), each hunk re-placed, `PATCH.md`'s line
   numbers updated. `scripts/ww3-gpu.sh`'s fork-versus-NOAA check must pass unchanged.
4. **Rerun the evidence on the new base:** `smoke`, `full`, `coast` resident pair to pair; the
   resident matrix with `WW3GPU_LAB_SWITCH=ON` (the entries of #191's U3); a `ww3_multi` entry;
   `WW_KOKKOS_VA_POISON=1` and `WW_KOKKOS_VA_COUNT=1`. Then `port_score.py --write`, and every
   page that cites `model/src/<file>.F90:<line>` at `80644ba9` or `03adda91` updated to the new
   pin (AGENTS.md says the pin's commit at the time of writing).
5. **Docs:** AGENTS.md, CONTRIBUTING.md and `docs/TOOLCHAIN.md` name the new pin and why it is
   a production branch; `README.md` and `README.pt-BR.md` together.

## Risks

- `GFS.v17` lacks 31 commits of `develop`; any of them that the KOKKOS patch or a translation
  relies on must be found in unit 2 or 3 ⚠ (not read).
- A production branch moves with NOAA's fixes; the pin is a commit, and moving it again is a
  deliberate change, as for every submodule here.
- The other session's NOAA study and its `W3SDS4` patch are written against `03adda91`; the
  patch is checked again on the new base with `scripts/ww3_fortran_ab.sh`.
