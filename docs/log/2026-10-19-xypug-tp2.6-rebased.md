# `ww3_tp2.6` on the rebased pin `aa382393` still gives the Fortran's bytes

2026-10-19, an agent for M. Hoffmann; issue #196,
[ADR-0016](../ADRs.md#adr-0016),
[WFIP-0003](../WFIPs/WFIP-0003-kokkos-regtest-matrix.md). Rerun of
[`2026-10-18-xypug-tp2.6.md`](2026-10-18-xypug-tp2.6.md) after the fork branch was rebased.

## Question

The 2026-10-18 run was at WW3 `84df86e0` (`ww3-gpu/xypug-196`). The branch was rebased onto main's
WW3 pin `fac74069` and is now `aa382393` (`ww3-gpu/xypug-196-rebased`). Does the rebased pin still
give the Fortran's bytes on the two `ww3_tp2.6` entries, and does the rectilinear `smoke` still
match?

## What was done

On the owner's i9-14900 (32 hardware threads, `nproc` 32, `OMP_NUM_THREADS=8` per matrix run), ww3-gpu
`94b3118` (branch `goal/196-port-w3xypug-rebased`), `WW3/` at `aa382393`, gfortran and g++ 16.2.0
(Nix wrapper, the build log's toolchain line), Kokkos OpenMP backend, no GPU command. `git status`
showed a clean tree at `94b3118` before and after. It ran, in order:

1. `WW_KOKKOS_VA_POISON=1 WW_KOKKOS_VA_COUNT=1 WW_KOKKOS_PROP3_COUNT=1 bash scripts/ww3-gpu.sh
   --ww3-gpu smoke --cpu --kokkos resident`.
2. `WW3GPU_KOKKOS=resident WW3GPU_LAB_SWITCH=ON just ww3-gpu-matrix 4 serial -R '^00[12]:'`.

## Result

- (v) Both `ww3_tp2.6` entries pass: `ST4` `test.comp` 0 of 36 files different, `ST4_ASCII` 0 of
  38, `nccmp-tol` PASS on `hs` and `t0m1`, `WW3GPU_STRICT=ON`, `ww3_self` not needed. Record:
  [`docs/data/ww3gpu_matrix_xypug_tp2.6_2026-10-19.tsv`](../data/ww3gpu_matrix_xypug_tp2.6_2026-10-19.tsv).
  Same counts as at `84df86e0`.
- (v) The kernel ran in both: 600 batched `W3XYPUG` calls on the resident `VA`, 777 600 spectral
  components (`kokkos_spectra` `XYPUG:777600`, `SRCE:0`), 981 600 `W3XYPFSN2` sub-steps, one `VA`
  host-to-device copy and none device-to-host.
- (v) `smoke` (rectilinear, `W3XYPUG` calls 0): the Kokkos run is byte-identical to the Fortran of the
  same executable (`nccmp-tol` `max|d| = 0`, every model file identical) and to `--ww3` (every model
  file but the NetCDF byte-identical, `nccmp-tol` PASS, `max|d| = 0`). Its `VA` copies: 1
  host-to-device, 37 device-to-host (one per output step, the reads before an output that the rule
  allows), 2124 partial column copies device-to-host.
- Each entry's wall time in the record (77 s and 80 s, against 118 s and 123 s on 2026-10-18) includes the Fortran and Kokkos runs and the comparison; load on the machine was not controlled, so it is not a timing ⚠.
- **Not exercised**, as on 2026-10-18: `W3KTP3` and the source terms on an unstructured grid
  (`FLCTH`, `FLCK`, `FLSOU` are off in `ww3_tp2.6`) ⚠.

## What it changes

`kokkos/ports.tsv` (`regtested` of `W3XYPUG` and `W3XYPFSN2`) and the two port reports cite the
rebased pin and this entry. The 2026-10-18 entry stays as written.
